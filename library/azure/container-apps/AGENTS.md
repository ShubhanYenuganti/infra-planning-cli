# container-apps-pp-cli - Agent Guide

A focused CLI for container-apps on azure. Generated by CLI Printing Press
v1.3.2 from the Azure Container Apps Swagger spec.

Spec sourced from azure-rest-api-specs as OpenAPI 2.0:
https://raw.githubusercontent.com/Azure/azure-rest-api-specs/main/specification/app/resource-manager/Microsoft.App/ContainerApps/stable/2024-03-01/ContainerApps.json
It is converted to OpenAPI 3.0 with `scripts/spec-to-openapi3.sh` before
generation.

## When to use this CLI

- Manage Azure Container Apps resources
- Inspect app state for debugging
- Export resource state to JSON for audit or diffing
- Use raw API passthrough where a promoted command is missing

## Authentication

Run `container-apps-pp-cli doctor` to verify auth and API connectivity. See
root [AGENTS.md](../../../AGENTS.md) "Auth resolution" for the Azure auth chain.

## Key subcommands

| Subcommand | Purpose |
|---|---|
| `api` | Raw API passthrough for any container-apps endpoint |
| `auth` | Manage authentication credentials |
| `doctor` | Health-check config, auth, and API reachability |
| `export` | Export resources to JSON |
| `import` | Import resources from JSON |
| `sync` | Sync resources to local SQLite cache (v1.1) |
| `search` | Full-text search over synced resources (v1.1) |
| `sql` | Raw SQL against local cache (v1.1) |

## Agent-friendly usage

Always pass `--agent` for minimal, parseable output:

```bash
container-apps-pp-cli --agent doctor
```

## Local cache

Data stored at `~/.infra-press/container-apps-pp-cli.db` (SQLite/FTS5). `sync`
populates it; `search` and `sql` query it offline.

## Known gaps (v1.0)

- Spec sourced from azure-rest-api-specs, not apis.guru; URL must be re-pinned on regen
- Azure ARM hierarchical paths and complex body schemas may be skipped or simplified by press
- `sync`/`search`/`sql` return "not yet implemented" - full SQLite backend lands in v1.1
